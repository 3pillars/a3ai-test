### Trap worth remembering

`GET https://api.flop.network/v1/enroll/wallet/challenge` returns **403** to Python's bare
`urllib.request` because it sends no `User-Agent`. Send a UA on both the challenge and the
enroll POST. A missing header reads exactly like an enrollment refusal.

### The trap that nearly cost it

The CLI request came back `FAUCET_OUTCOME_UNKNOWN` (30 s HTTP timeout) and the faucet had
**already paid**. My fallback then signed a *second, different* nonce and got
`429 ip_cooldown` ("This IP funded recently; retry in 1440 min") — which is only possible if
that IP had just been funded. Reconciling the original nonce returned the recorded grant
(`200`, `status: finalized`).

Rules learned:
1. A timeout / `FAUCET_OUTCOME_UNKNOWN` means the money may already be yours. Never sign a new
   nonce — repeat the same address+nonce+signature.
2. `429 ip_cooldown` is *evidence a prior grant landed*, not a sign the pool is empty.
   `daily_cap_reached` = pool full; `ip_cooldown` = your IP already served. Read `reason`.
3. Check the chain balance before concluding anything; a nonzero balance with
   `accountNextIndex == 0` is an inbound grant.
4. `ip_cooldown` is 24 h per IP, and the agent lane also has `rolloverRequiresSpend: true`, so
   the D10 lane realistically yields 10 FLOP per IP per day, once, until Testnet compute opens.
