Now the source, because this is the part that was hidden. The tweet has no media and no visible link. It is a note tweet quoting a post from the official Deep Seek Harness account, forty eight thousand six hundred sixty four followers, verified, bio "everything is a plugin." That post went up November first, eleven thirty seven a.m. U T C, which is six thirty seven a.m. Eastern, and its entire text is just a link to an X article. The article is titled "Exploring Super-agent Design: Towards a More Autonomous Agent System." About six thousand nine hundred words, twenty seven sections. The author writes on behalf of the Deep Seek Harness team, and thanks about sixteen named reviewers. And there are three disclaimers at the top of the article itself that Saravia's tweet does not carry. One, the original is in Chinese and the version we are reading is a machine translation. Two, this article discusses architectural ideas and is not an introduction to existing features of Deep Seek Harness. Now the product itself, because a lot of people will assume this is vaporware and it is not. Deep Seek Harness is real, official, and open source. The product page says it is now in public preview worldwide and open source, with composable plugins that extend what agents can do. The GitHub repo has two hundred sixty eight thousand four hundred thirty stars, MIT licensed, created August thirteenth twenty twenty six, and the README warns it is in developer preview and iterating rapidly and there will be compatibility breaking changes. Underneath it is a real paper, "A Programming Paradigm for Spatiotemporal Composability," there is also an underlying framework that the team gave a name to, published on the online paper archive in twenty six oh eight dot twenty five five twelve, August twenty sixth, authored by a research team at that company with several colleagues listed. Now let me map Saravia's language onto the article, because this is where he earns credibility. He says coordination execution architecture. That is section two, the two level architecture, a long lived Router layer described as the global sequence point, the coordination point and the memory, with a context isolated Worker layer carrying a full set of execution tools per task. He says event triggering and acting ahead. That is section three, with triggers defined as semi structured events from the environment, things like group chat, email, calendar, code review, C I, and acting ahead defined as speculative execution, quote, the agent starts work in the background before it knows whether the result will be used, results that turn out to be useful are delivered and the rest are discarded. He says asynchronous ReAct loop. That is section four point one, full duplex, and the article says they replace time consuming command and tool calls with asynchronous start and stop calls, turning the loop into an asynchronous ReAct loop. It even says Deep Seek Harness already implements this mechanism but it is not yet enabled by default. He says separates state, compute and environment. Section five, separating compute, state and environments, and the article says it borrows compute storage separation from computer systems, with the agent loop in the cloud leaving state heavy execution environments where they are, plus bring your own machine. And he says persist and always available across devices, section five and section six, the watchdog, quote, always online, and when a user's personal device reconnects the cloud agent automatically starts and completes the tasks that need to run on that device.

So every architectural noun in his tweet maps one to one onto a named section. He is not inventing a framework. He is accurately summarizing one. One exception, and it is worth flagging. He says the design scales through state management and sandboxes. The article does not say that. Section five says it scales through compute, state and environment separation. Sandboxes appear only in Anthropic's variant and in the security caveats. So he slipped a word in, and it happens to be the word that sounds most security-conscious.

Now the verdicts on his substantive claims. Coordination execution architecture is supported. It is a real, named pattern. Anthropic's own research system uses what they call an orchestrator worker pattern, where a lead agent coordinates the process while delegating to specialized subagents running in parallel. Deep Seek's Router and Worker split is the same idea with the coordinator explicitly barred from executing tasks itself.

Asynchronous ReAct loop is the one that gets overplayed. I searched arXiv full text and abstract for that exact phrase and got zero papers. This is Deep Seek's own coinage from October thirty first twenty twenty six, which Saravia inherited from the source. It is not a validated term with an independent literature. The concept of non blocking tool calls does have analogues, Anthropic's Managed Agents explicitly pitch themselves as best for long running tasks and asynchronous work, but the name is new, and Saravia presenting it as an established pattern would be overstating it.

Event triggering and acting ahead is supported as a shipped industry capability. Anthropic shipped scheduled agent runs, called routines, on April fourteenth twenty twenty six, running in the cloud on a schedule, on A P I calls, or on GitHub events. OpenAI shipped scheduled agent execution two days later. So the direction is sound. But Deep Seek's specific "acting ahead" is speculative execution living in a prototype whose own README says it is not identical to the implementation described in the article, and that some designs in the article are not implemented in the prototype at all.

State, compute and environment separation is supported and this is the strongest part of his post. Deep Seek's two level decoupling is independently mirrored by Anthropic's Managed Agents, which virtualizes the components of an agent, a session, a harness, and a sandbox, as separately swappable interfaces. Two independent large labs converging on the same separation is real signal.

Persistence across devices is supported and shipped. OpenAI gave Codex reusable cloud environments at DevDay, September twenty ninth, persistent and accessible from computers, phones and cloud, and Anthropic's scheduled routines run cloud side even when your device is off.

Now the claim I think is weakest. "L L M agents have gotten better at coordination and maintaining persistent context." Coordination, partially. Anthropic reports multi agent with an Opus lead and Sonnet subagents beating single agent Opus by ninety point two percent on their internal research eval, but that burns about fifteen times the tokens, and the Berkeley M A S T work found multi agent L L M systems fail forty one to eighty six point seven percent of the time across fourteen failure modes. Persistent context is weaker still, because Deep Seek's own section eight point one concedes memory limits how far the system can scale and that this trade off will remain until the global memory problem is solved. The source admits the limit Saravia glosses over.

His other claim, that you can do this with other harnesses, is directionally true. LangGraph has checkpointers and stores and durable execution with resume after interruption. The OpenAI Agents SDK has sessions with S Q L, Redis, Mongo and encrypted variants, plus handoffs, agents as tools and sandbox clients. Anthropic has Managed Agents and multi agent orchestration. C R E W A I and A U T O G E N are weaker on durable resume because they are in process by default. And here is the honest caveat: none of them ships the full combination of event driven triggers, the Router and Worker split, and the watchdog. That combination is what the Deep Seek prototype uniquely provides, and it is explicitly research code.

Now the caveats he dropped. The article's own experiments are self reported and weak. Section seven says the experiments use synthetic workloads and simplified environments, that parts of the setup could be more rigorous, so the results are indicative only. Coding was simulated by a tool that simply consumes time. Sample size, five runs. Super agent median twelve point four minutes, ninety fifth percentile fifteen point seven, versus twenty nine point five for a single session with a subagent, and with a neutral prompt the model did not call a subagent in any of the five runs. No peer review, no external replication, no arXiv version of the article itself. On Hacker News the harness has strong traction but this specific article has almost none, two points.

Security is the bigger one, and this is Deep Seek's own safety notice. Deep Seek Harness is experimental developer preview software. It has not undergone a security audit and must not be treated as secure or production ready. On sandboxing specifically, sandboxing, approval prompts and permission controls can reduce risk but they do not guarantee isolation, and do not rely on Deep Seek Harness as the sole security control for untrusted workloads. The article's own section eight point four adds that bring your own machine implicitly assumes the cloud and the endpoints trust each other, and that credentials can leak even if the cloud is never compromised, because as long as credentials on an endpoint can enter the model's context, normal execution can expose them. No solution is proposed. That is an open problem the author leaves open.

One last thing on Saravia's framing. He calls it an "absolute masterclass" and "the best write up I have read on how I have been working with my agent teams powered by my custom harness." Read that second sentence closely. Part of the endorsement is a self reference to his own harness. That is not disqualifying, it is just something to know when you weigh the recommendation. The source says the experiments are indicative only and the implementation is a prototype. The tweet says masterclass.

Bottom line. This is a genuine, high quality pointer to a real, technically literate architecture document. The concepts are largely sound, and where it matters most, the separation of concerns, event driven execution, and cross device persistence, they are independently corroborated by Anthropic and OpenAI shipping equivalents. What is not backed by external validation is the vocabulary, specifically the async ReAct loop, the headline numbers, which are unreplicated synthetic benchmarks of five runs, and the masterclass framing on a machine translated, vendor published, non peer reviewed design doc. Read it, steal the architecture, ignore the adjectives. And if you are going to run Deep Seek Harness on anything real, do not trust it with credentials you care about, because the vendor itself says it has not been security audited.
